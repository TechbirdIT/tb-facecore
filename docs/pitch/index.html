End-to-end in five moves

From a face in front of a camera
to attendance in HRMS.

01

Enroll

Employee self-registers a webcam photo at /face. The image is embedded into a 512-d vector — then discarded.

02

Approve

HR runs the Face Profile Approval workflow. Only Approved profiles ever sync to devices.

03

Sync to edge

Each camera device pulls approved embeddings incrementally and caches them locally — no per-frame network hop.

04

Recognise

Edge detects, tracks & matches in milliseconds. Passive liveness blocks photo/video spoofs — identity resolved once per track.

05

Check-in

A signed event is posted; the server creates the Employee Checkin and HRMS's native engine derives attendance.

data flowing · camera → edge → frappe

No parallel attendance logic — FaceCore feeds Frappe HRMS's native shift auto-attendance. Every sighting also builds a fair presence-hours timeline.

Capabilities

Everything a serious deployment needs — and the fairness others skip.

Sub-second edge recognition

InsightFace buffalo_l (SCRFD detector + ArcFace r50) produces a 512-d embedding; an in-memory NumPy cosine match is sub-millisecond up to ~50k faces per site. Each edge holds only its own location's faces.

SCRFD ArcFace ONNX

Passive anti-spoof liveness

MiniFASNet rejects printed photos and screen-replay attacks with zero user interaction — no blink, no head-turn. A flat photo scores near-zero and is refused.

Fair presence-hours

Sightings stitch into Presence Sessions per area — a session only ends after a configurable gap (default 12 min). A short break doesn't end the day; a long lunch isn't counted.

Cross-camera cooldown

Dozens of sightings across many cameras collapse to one check-in per window. No double-counting.

Device fleet health

Heartbeats, last-seen, app version & automatic stale-device detection across the whole edge fleet.

Employee self-service

A frappe-ui SPA at /face: webcam register, live status, and a rate-limited self-test.

Privacy by design

Embeddings are one-way transforms — you cannot reconstruct a face from them. The enrollment image is discarded after embedding, the vector field is permission-restricted in Desk, and consent text + version are captured per profile.

Full audit trail & offline queue

Every recognition is a Face Recognition Event with similarity/liveness scores, device linkage and a deduplication index. Edge devices keep a durable SQLite queue and drain it automatically when the network returns.

Dual-engine architecture

Two engines, two jobs — deliberately not merged.

A fast, light edge engine answers "who is this, right now?" for attendance. A separate heavy analytics sidecar answers "what can we learn from this face?" They scale and fail independently behind one gateway.

Deploy

Two repos. A handful of commands.

The Frappe app and the AI stack blend over a single authenticated HTTP seam — no code merge.

1

Frappe app — the system of record

# in your bench
bench get-app TechbirdIT/tb_face_attendance
bench --site your.site install-app tb_face_attendance
bench --site your.site migrate

Brings the DocTypes, approval workflow, sync/event APIs and the /face portal.

2

AI stack — the edge engine

git clone --recurse-submodules TechbirdIT/tb-facecore
cd tb-facecore
./install.sh # venv + models + .env secret
make run # ai_service on :8080

Prints a generated AI_SERVICE_SECRET to paste into Frappe.

3

Wire the seam

In Face Recognition Settings set:

Embedding Service URLhttp://localhost:8080
Embedding Service Secret= AI_SERVICE_SECRET

The app sends it as an X-Secret header to /embed.

4

Enroll & register a camera

  • › Give each Employee a unique Attendance Device ID.
  • › Employee registers a face at /face → HR approves it.
  • › Create a Face Edge Device user (least-privilege role) + API key.
  • › Point edge_client/config.yaml at the camera & device — done.

Optional analytics: ./install.sh --with-sidecar brings up the DeepFace stack.
